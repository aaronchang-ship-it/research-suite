# modeler — plant 數學模型建模工作流 v1.0

> 📋 版本變更見 `CHANGELOG.md`。

定位：pxa-literature 的**下游**（另一條下游是 pxa-scribe）。literature 的 source note
「工程實踐」節（實作標的、介面定義、驗證點）是現成輸入。

本 skill 提供三樣東西，其餘不管：

| 本 skill 提供 | 不提供（交給誰） |
|---|---|
| **分層架構**：一個元件怎麼分成 L1 / L2 / L3，各級之間的約束 | Simulink 方塊怎麼加、怎麼接、怎麼排（MathWorks 官方 skill，見 §8） |
| **驗證流程**：模型要通過哪幾關、每一關能宣稱什麼 | `sim`、`linearize`、辨識、測試框架的用法（同上） |
| **決策與留痕**：誰決定、寫在哪、什麼算定案 | 專案的寫入授權、資料夾、命名前綴（專案 `CLAUDE.md`） |

每個模組的方程式、參數值、驗證數字與決策只寫在該模組的**規格 md**，那是唯一真相。

## 1. 工作流總覽
每一階段結束有一個關卡；關卡沒過不進下一階段。

| # | 階段 | 做什麼 | 關卡（誰判定） | 官方 skill | 產出 |
|---|---|---|---|---|---|
| 1 | 證據盤點 | 列出手上的論文、規格書、測試資料，各自能支撐什麼（§2） | 使用者確認證據清單與可信度 | `pdf` | 規格 md「資料來源與可信度」 |
| 2 | 分層規劃 | 決定要建到哪一級、共同介面、每一級加哪一類物理（§3） | 使用者定案（決策紀錄） | `specifying-plant-models` | 規格 md「共同介面」 |
| 3 | 數學模型 | 寫完該級的方程式、參數表、假設與有效範圍（§4） | 式子對原文核對；使用者審閱 | — | 規格 md 該級章節 |
| 4 | 參數 | 每個型號一支 preset 腳本，每個欄位標單位與來源 | 參數表與規格 md 一致 | `matlab-import-export-data` | preset `.m` → `.mat` |
| 5 | 實作 | 照方程式建方塊，附「方程式 → 方塊」對照 | 結構檢查無 error | `building-simulink-models` | 該級方塊、單模組 harness |
| 6 | 驗證 | 走驗證階梯 V1 → V5（§5） | 每一階的判定準則 | `simulating-simulink-models`、`simulink-linearize` | 測試檔、回放報告 |
| 7 | 收尾 | 更新規格 md 與導讀，回報變更檔案清單 | 使用者驗收 | — | 規格 md、導讀 HTML |

- 一次對話只做一個模組的一個階段（或一個等級、一次驗證）。
- 新增一個等級＝從階段 2 再走一輪，不是在舊方塊上加東西。
- 階段 3 在階段 5 之前：**先有數學模型，才有方塊**。

## 2. 三種證據
| 證據 | 決定什麼 | 準則 |
|---|---|---|
| 論文 | 模型**結構**與方程式 | 引用寫「作者 年份 式 (n) / 節 / 頁」；式子對原文核對，未核對標 `<?>` |
| 規格書 | **參數**初值與曲線 | 引用寫「文件名 版本 表 / 圖 / 頁」；寫清楚測試條件；曲線數位化記錄解析度與校正方式 |
| 測試資料 | 參數**辨識**與**驗證** | 記錄日期、設備、取樣率、濾波、通道與單位；原檔只增不改；辨識用與驗證用的資料分開 |

- **保真度由證據決定**：沒有資料能驗證的動態不建。先盤點證據，再決定建到哪一級。
- **禁止記憶引用**：只引用專案內實際存在的檔案（依檔名寫，不猜作者縮寫），或當輪
  搜尋查證、附連結的文獻。
- **證據互相矛盾**（例：製造商多項式與台架量測差兩成）→ 列差異與可能原因，由
  使用者裁定採信哪一個，不自行平均、不默默擇一。
- 暫定值、假設值、借用其他元件形狀的值一律標 `<?>`，列入規格 md 待釐清表。
- **買來的模組當黑箱**：只用「已知且會改變 plant 行為」的參數描述，主要是限制
  （比例、電壓 / 電流 / 速度上限）與哪些功能被關掉。廠商內部調校值不是驗證依據，
  動態由量測取得。收到廠商參數檔先逐項分類：採用／確認未建模／僅記錄／無關。

## 3. 分層架構 L1 → L2 → L3
同一個元件在不同階段要回答不同問題，所以分級建模，**每一級只加一類物理**。

| 等級 | 回答的問題 | 加入的物理 | 典型用途 |
|---|---|---|---|
| L1 | 命令到輸出的主要動態是什麼 | 主要時間常數、延遲、主要限制 | 控制設計（要能線性化）、能量預算 |
| L2 | 內部狀態怎麼影響輸出 | 電氣 / 控制器 / 內部動態；限流、飽和、再生 | 限制邊界、MIL |
| L3 | 外部負載與環境怎麼影響輸出 | 來流、密度、溫度、氣動負載、老化 | 飛行包絡、回放比對 |

> 命名提醒：這裡的 L1–L3 是**模型保真度**，與 pxa-literature 的 `evidence_level`
> （L1–L4）及 pxa-standards 的文獻層級（L1–L3）是三件事。文件中首次出現寫全稱
> 「保真度 L2」。

**共同介面**先定，三級共用。每個埠歸入一類：

| 類別 | 意義 | 與分級的關係 |
|---|---|---|
| u | 命令輸入（來自控制器） | 三級都用 |
| w | 外部擾動 / 環境（來流、密度、溫度、母線電壓） | 低等級接 Terminator，高等級才用 |
| y | 給控制器或其他模組的輸出 | 三級都有 |
| z | 內部真值，供除錯與回放比對 | 低等級沒有這個量時，以合理的代替值輸出並註明 |

三條約束：
1. **同一組埠**：三級的輸入 / 輸出完全相同；整合層換等級只換方塊，不重拉線。
   新等級需要新埠時，先討論低等級怎麼也有這個埠，再動。
2. **退化一致**：新增的物理關掉時，高一級在數值上等於低一級（例：L3 在來流為零、
   標準密度下等於 L2；L2 在穩態未飽和時等於 L1）。這是驗證階梯的 V2。
3. **換型號只換參數**：同一種模組換型號時結構不變；參數 struct 以元件型號命名、
   扁平一層，每個型號一支 preset 腳本。

整合順序同樣分層：**模組 → 次系統 → 整機**。模組層可包成 library 方塊；次系統 /
整合層預設是把模組方塊直接接起來的平面模型，使用者要求時才包 library、加 mask。

## 4. 數學模型先行（規格 md）
動任何方塊之前，該級在規格 md 要先寫完：

| 項目 | 內容 |
|---|---|
| 狀態、輸入、輸出 | 符號、單位、正負號；輸入輸出對應 §3 的 u / w / y / z |
| 方程式 | 每條附來源（論文式號，或自行推導並寫出推導依據）；表格＋Mermaid 訊號流 |
| 假設與有效範圍 | 這一級忽略了什麼、在什麼條件下成立 |
| 參數表 | 名稱 × 值 × 單位 × 來源 × 測試條件 × 是否 `<?>` |
| 可辨識性 | 哪些參數能由規格書取得、哪些要測試資料辨識、哪些目前無資料可定 |
| 數值處理 | algebraic loop 用封閉解消除；時間常數遠小於步長的子狀態用 ZOH 精確離散解 |

實作後補一張「方程式 → 方塊」對照表，讓任何人能從式子找到方塊。

規格 md 的章節：1 檔案 → 2 資料來源與可信度 → 3 共同介面 → 各等級（方程式、方塊
對照、參數、模擬結果）→ 驗證 → 待釐清 `<?>` → 對外議題 → 決策紀錄 → 文獻。

Simulink 的建模判斷與版面慣例見 `references/simulink-conventions.md`。

## 5. 驗證流程
### 5.1 驗證階梯
由下往上走；下一階沒過，上一階的結果不算數。

| 階 | 驗證 | 比的對象 | 性質 | 判定 |
|---|---|---|---|---|
| V1 | 實作檢查 | 模型自己用的封閉解、查表、方程式手算點 | 自洽 | 相對 1e-9 等級；不過就是實作錯 |
| V2 | 等級一致 | 低一級的模型，在退化條件下 | 退化一致 | 相對 1e-9 |
| V3 | 對規格書 | 規格書的曲線 / 表格，在它的測試條件下 | 對規格書 | 容差寫在測試檔頭，註明理由與實測值 |
| V4 | 對台架 / 地面測試 | 原始時序輸入 → 單模組 harness → 比輸出（穩態點＋動態段） | 對量測 | 同上；辨識用過的資料不拿來驗證 |
| V5 | HIL / 飛測回放 | log 以 ZOH 重取樣 → 開迴路回放 | 對量測 | 相關係數、RMS、最大誤差；殘差說明來源，不直接視為模型錯誤 |

另外兩項依用途加做：
- **線性化**（L1，或任何要拿去做控制設計的等級）：線性模型 vs 非線性小階躍，列
  最大差與原因；有飽和 / 切換時用頻率響應估測交叉確認。
- **整合**：模組各自過完 V1–V4 後才接成次系統；次系統先開迴路、再閉迴路。

### 5.2 驗證性質四分類（硬規則；待回寫 pxa-standards 正本）
每個測試、每張比較圖都標明性質。

| 性質 | 能宣稱什麼 | 不能宣稱什麼 |
|---|---|---|
| 自洽 | 實作沒寫錯 | 模型符合實物 |
| 退化一致 | 分級之間沒有矛盾 | 任何一級符合實物 |
| 對規格書 | 模型重現廠商在該條件下宣稱的行為 | 實物真的如此；若該曲線就是參數來源，只算自洽 |
| 對量測 | 模型在該資料涵蓋的條件範圍內重現實物 | 範圍以外的行為 |

### 5.3 回報紀律
- **不可把自洽或退化一致說成驗證過實物。**
- 只回報實際跑過的結果；沒跑的標「未驗證」；尚未決定驗收標準時明寫「未定驗收標準」。
- 容差收緊或放寬先問使用者，不為了讓測試通過而調容差。
- 每個數字可追溯：檔案、腳本、日期、工具版本、log 的 metadata。
- 測試只驅動模型並比對輸出，不在測試裡重寫一份模型邏輯。

## 6. 決策與留痕
| 事項 | 規則 |
|---|---|
| 架構決策（結構、介面、分級、容差） | 先列「選項 × 差異 × 取捨」，最多一行建議；使用者定案後才動模型 |
| 決策紀錄 | 寫進規格 md，編號（D1、D2…）附日期與理由 |
| 待釐清 `<?>` | 列表追蹤；轉正要有證據，並寫明依據 |
| 對外議題 | 要其他模組或整合層處理的事，寫在自己的規格 md，由使用者彙整 |
| 規格 md 更新節奏 | 開發中不必每個小改動都更新；回覆中用一行記下 md 與模型的差異，到里程碑（模型凍結、驗證完成）再一次更新。已知錯誤的陳述仍要當場回報 |

## 7. 交付文件
| 文件 | 讀者 | 要求 |
|---|---|---|
| 規格 md | 建模者與協作的 Claude session | 唯一真相 |
| 圖解導讀 HTML | 接手的人 | 快速看懂全貌：每章「在解決什麼」「為什麼這樣設計」、好處與代價；數字只取自規格 md 與參數檔；只寫已定案、已建的內容 |
| 技術報告 / 簡報 | 其他次系統的夥伴、審查者 | 測試細節：原理、方法、結果、結論、改進建議；正式報告交 pxa-scribe |

三者合起來要能當成給法規單位或客戶的證據，所以一律適用 §5.2 與 §5.3。

## 8. 與 MathWorks 官方 skill 的分工
工具操作一律照官方 skill，**用到時載入，不憑記憶**。本 skill 與官方不同之處只有
下表，其餘衝突以官方為準。

| 項目 | 官方做法 | 本 skill 的做法 | 理由 |
|---|---|---|---|
| 規格文件 | `specifying-plant-models`：system / architecture / implementation plan / test plan 分檔 | 單一規格 md；吸收官方的 u / w / y / z 分類、參數表欄位與 review gate | 一個模組一份真相 |
| 版面 | `model_edit` 自動排版 | 使用者手排過的方塊是範本；以 `model_edit` 的 `configure Position` 精確放置、`layout_mode` 用 `incremental`，不對手排過的圖做 full layout | 使用者要一眼看出主訊號流 |
| 測試 | `testing-simulink-models`（需 Simulink Test） | 有 Simulink Test 時照官方；沒有時用 `matlab.unittest` ＋ `Simulink.SimulationInput` | 官方 skill 自己指定的退回路徑 |

依階段會用到的官方 skill：

| 階段 | Skill |
|---|---|
| 分層規劃 | `specifying-plant-models` |
| 實作 | `building-simulink-models`、`arranging-simulink-layouts` |
| 模擬 / 回放 | `simulating-simulink-models`、`authoring-simulink-inputs` |
| 線性化 | `simulink-linearize`、`simulink-frequency-response` |
| 辨識 / 擬合 | `matlab-identify-linear-system`、`matlab-solve-optimization` |
| 資料前處理 | `matlab-import-export-data`、`matlab-prepare-signal-data` |
| 測試 | `matlab-write-tests`、`testing-simulink-models` |
| 專案檔與 path | `managing-simulink-projects` |
| 整合層重用模組方塊 | `setup-custom-libraries` |

工具操作上實際踩過的坑見 `references/matlab-mcp-pitfalls.md`（補充官方 skill，不取代）。

## 9. 合規紅線
1. 沒有數學模型（規格 md 該級章節）不建方塊。
2. 架構決策未經使用者定案不動模型。
3. 不憑記憶列文獻、不猜作者與式號。
4. 證據矛盾不自行平均；`<?>` 不默默轉正。
5. 自洽與退化一致不說成驗證過實物；沒跑過的不說通過。
6. 不為了通過測試調容差；不改原始資料檔。
7. 共用的 MATLAB session 是使用者的：只關自己開的模型，清 workspace 前先說。
