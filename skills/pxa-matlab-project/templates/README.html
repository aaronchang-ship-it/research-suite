0. 這份文件怎麼讀

這是專案的總說明書，目的是讓第一次接觸本專案的人在一小時內知道：專案在做什麼、程式怎麼分層、每個資料夾放什麼、要照什麼順序執行、產出在哪裡、有哪些規則不能違反。文件自成一體，不需要其他對話紀錄即可閱讀。

專案內容分三種狀態，以標籤區分：

  • 已有 檔案存在，流程已建立並使用中。
  • 待整理 檔案存在，但與目前的規劃不一致，或流程尚未走完。
  • 待建 已規劃、資料夾已開，但內容尚未建立。
與其他文件的關係：CLAUDE.md 是協作規則的正式版本（授權、寫入流程、撰碼慣例），本文件第 11 節只是摘要；兩者有出入時以 CLAUDE.md 為準。README.md 是本文件的文字精簡版，資料夾、流程與命名必須與本文件一致。

路徑一律以專案根目錄為起點，寫成 design\〔domain〕\ 這種相對形式。

2. 快速開始

  1. 以 MATLAB 開啟 〔PROJECT〕.prj。Project 會設定路徑；所有腳本都假設 current folder 是專案根目錄。
  2. 確認 workspace\ 內有基礎資料檔：〔列出檔名〕。
  3. 進入 design\〔domain〕\，依第 5 節的順序執行：〔init → trim → linearize → design → sim〕。
  4. 結果的 .mat 在 workspace\；人可以直接讀的報表與圖在 output\〔子資料夾〕\。
  5. 〔要把結果交給下游時怎麼做，見第 9 節。〕
執行前先知道：〔哪些腳本會覆寫 workspace\ 與 output\ 的檔案、哪些會清掉 base workspace、哪些執行時間長。〕

3. 軟體架構圖（分層）

由上而下八層，上層依賴下層。右側兩條直柱是跨層的共通機制。藍底方塊是已規劃但尚未建立的位置。

相依鏈

data\ → workspace\*.mat → library\ → model\ → { design\ , harness\ } → output\

各層責任

層資料夾責任不做的事
分系統與測試資料data\保存分系統原始交付與整合測試紀錄；前處理腳本把原始資料轉成 .matsource 只增不改
參數與結果workspace\全專案唯一的 .mat 交換區不放腳本
模組庫library\可跨機型重用的次系統；數值一律由 workspace\*.mat 提供不直接讀 data\
主模型model\整機組裝，用來 trim、線性化、跑 SIL不含測試
設計與驗證design\、harness\、veristand\設計；次系統與模組的驗證；即時目標機模型取參數與驗證不用同一筆資料
交付成果output\、documents\人可以直接讀的報表、圖、交接檔、技術報告腳本不回頭讀 output\〔例外寫在第 9 節〕
判斷一個模型該放哪裡：換機型只換參數就能用，放 library\；拿來 trim、線性化、跑 SIL，放 model\；刪掉後整機模擬仍能跑，放 harness\。

13. 接手者的第一天

  1. 讀本文件第 1–5 節，再讀 CLAUDE.md 的授權與撰碼兩節。
  2. 開啟 〔PROJECT〕.prj，開啟主模型，對照第 6 節看一遍次系統。
  3. 開啟 〔一支代表性的腳本〕，讀檔頭：這是全專案檔頭與流程寫法的範本。
  4. 開啟 〔一份代表性的報表〕，對照第 7 節看懂每一列。
  5. 依序執行一條流程：〔腳本順序〕。執行前先確認 workspace\ 與 output\ 已在版本控制內或已備份。
  6. 挑第 12 節的一項待整理事項，與負責人確認後開始。
修改任何東西之前先問自己三件事：這個檔案在保護清單內嗎？改動後下游腳本讀到的 workspace\*.mat 欄位還一致嗎？〔平行的 domain〕需要同步修改嗎？
