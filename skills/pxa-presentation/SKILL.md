# presentation — 由既有內容產出簡報 v0.1（草稿）

> 📋 版本變更見 `CHANGELOG.md`。
> **本 skill 尚未完成**：簡報種類、來源、上下游關係、版型與格式已定；流程、固定章節、每頁寫法、驗收條件尚未定案。
> 被呼叫時先告知使用者這一點，並就 §6「待定事項」中與本次工作有關的項目逐一確認，不自行假設。

定位：research-suite「研究流程與報告撰寫」這條線的下游之一。`pxa-scribe` 產出報告，
本 skill 把已經存在的內容轉成簡報；兩者依產出媒介分工。

## 1. 來源

簡報內容只能來自下列四種來源，每一頁都要能指回來源。

| # | 來源 | 說明 |
|---|---|---|
| 1 | 本次對話的內容 | 對話中已經確認的結論、表格、圖 |
| 2 | `pxa-scribe` 產出的技術報告 | `documents/{STRN}.md` 或其 docx |
| 3 | `pxa-literature` 建立的 Obsidian 知識庫 | source note、atomic note、MOC |
| 4 | 專案的 `output\` 資料夾 | 設計、模擬、測試分析後的產出（`.xlsx` / `.txt` / 參數檔 / 圖檔）；依 `pxa-matlab-project` 的定義，是給人直接看、也可供撈取資料的資料夾 |

第 4 種只取 `output\`，不回頭讀 `workspace\` 的 `.mat` 或 `data\` 的原始資料；`output\` 沒有的圖表或數字，
回上游由設計或分析腳本產出，不在簡報階段自行計算或重畫。

四種來源都沒有時，不產出簡報：先請使用者指定來源，或改用 `pxa-scribe` / `pxa-literature` 把內容建立起來。
各種簡報可以取用哪些來源見 §3。

## 2. 簡報種類

依「對象想帶走什麼」分三種，另有一種由其中兩種濃縮的衍生版。

| 種類 | 對象 | 對象要帶走的 | 篇幅與重心 |
|---|---|---|---|
| 1. 進度匯報 | 主管、同仁 | 做了什麼、結論、需要誰決定什麼 | 短；第一頁就是結論與待決事項 |
| 2. 技術審查 | 其他分系統、審查者 | 方法是否站得住、證據在哪、結果是否符合需求 | 長；每個結論頁對應報告的結論編號與圖表編號 |
| 3. 導讀教學 | 接手者、新進同仁 | 主題的概念與脈絡、該從哪裡讀起 | 中；由概念到方法到範例，附延伸閱讀 |
| 對外簡報（衍生） | 客戶、主管機關 | 背景與結果的濃縮 | 由第 3 種取背景、第 2 種取結果 |

技術審查不再細分種類：同一套規則以剪裁表區分階段——**設計階段**（設計完成、準備進入驗證前）
與**檢核階段**（測試或驗證結果已收進報告之後）。剪裁表內容待定（§6-b）。

## 3. 上下游關係

```
知識合成               設計                    撈結果與檢核
pxa-scout ─┐
pxa-literature          pxa-modeler 等          模擬、測試、回放
（知識庫）               （模型、設計腳本）         （結果檔、圖表）
    │                       │                        │
    │                       │                        │
    │                       ├──── 專案 output\ ───────┤
    │                       │   （報表、參數檔、圖檔）   │
    │                       └────── pxa-scribe ──────┘
    │                         （設計階段報告／檢核階段報告）
    ▼                                   ▼
 3. 導讀教學                       2. 技術審查（報告＋output\）
 （概念、脈絡、方法）                （設計階段／檢核階段）
    │                                   │
    └──────────────┬────────────────────┘
                   ▼
              對外簡報（濃縮版）

 1. 進度匯報：不在主鏈上，任何階段都可以做
```

| 簡報 | 上游（可取用的來源） | 下游 | 時機 |
|---|---|---|---|
| 3. 導讀教學 | 知識庫（主）；scribe 報告的背景與方法章節 | 對外簡報的背景段 | 知識合成完成後；設計開始前讓團隊有共同基礎 |
| 2. 技術審查（設計階段） | scribe 設計階段報告＋專案 `output\` 的設計產出；知識庫補方法依據 | 對外簡報；檢核階段的審查基準 | 設計完成、準備進入驗證前 |
| 2. 技術審查（檢核階段） | scribe 檢核階段報告（測試、驗證結果）＋專案 `output\` 的模擬與測試分析產出 | 對外簡報的結果段 | 結果已收進報告之後 |
| 對外簡報 | 只取導讀教學與技術審查兩份簡報 | 無 | 兩份上游簡報定稿後 |
| 1. 進度匯報 | 對話內容、報告與知識庫的現況 | 無 | 任何時間 |

## 4. 由上下游關係推出的規則

| # | 規則 | 理由 |
|---|---|---|
| 1 | 技術審查一定要先有 `pxa-scribe` 報告；只有對話內容或結果檔時，先用 `pxa-scribe` 產出報告，再做簡報 | 審查簡報的每個結論都有報告可查，能當證據 |
| 1a | 技術審查中，結論取自報告，圖表與數值可取自報告或 `output\`；`output\` 的數字與報告不一致時列出來回報，不自行挑一個用 | 報告是結論的依據，`output\` 是最新的分析產出，兩者可能不同版 |
| 2 | 下游簡報不新增上游沒有的內容；缺內容時回上游補，不在簡報裡補 | 每一頁都能指回來源 |
| 3 | 對外簡報只濃縮、不改寫結論；另加三項限制：去識別化、不放未驗證的數字、每頁標來源與版次 | 簡報本身要能當證據 |
| 4 | 上游改版時，下游簡報標示為待更新 | 避免簡報與報告的數字不一致 |
| 5 | 進度匯報的內容不被其他簡報引用 | 它記錄的是當下狀態，可能尚未驗證 |

## 5. 版型與格式

| 項目 | 規定 |
|---|---|
| 產出格式 | 可編輯的 `.pptx`；頁面比例 16:9（960 × 540 pt） |
| 順序 | 先產出文字大綱（MD），使用者確認內容後才轉成 `.pptx`；內容錯誤在轉檔前攔下 |
| 範本 | `templates/pxa_presentation_template.potx`：原生 PowerPoint 範本，含母片、佈景主題與十種版面；不經 Claude 也能直接使用 |
| 示範 | `templates/pxa_presentation_demo.pptx`：每種版面各一頁，內容為虛構的版型示意 |
| 重建 | `scripts/build_template.ps1`（需要本機有 PowerPoint）；改版型時改腳本後重建，不手改範本 |

### 5.1 佈景主題

| 項目 | 內容 |
|---|---|
| 配色與字型 | 值見 `pxa-cis` §4、§6；範本的佈景主題已依該處的角色設定 |
| 字級 | 標題 28 pt 粗體；內文三階 18 / 16 / 14 pt；來源註與頁尾 10 pt；內文不小於 14 pt |

顏色一律取佈景主題色，不寫死色碼；圖形、表格、圖表才會跟著範本走。
投影片上的方塊圖、流程圖依 `pxa-diagram` 繪製；圖內的角色色不受「唯一強調色」限制。

### 5.2 十種版面

| # | 版面 | 佔位框 | 用在 |
|---|---|---|---|
| 1 | 封面 | 標題、副標題（簡報種類｜階段）、單位與報告人、報告編號與版次 | 第一頁 |
| 2 | 章節頁 | 章號、章節標題、導言 | 每章開頭 |
| 3 | 標題及內文 | 內文、來源 | 方法、說明 |
| 4 | 圖與說明 | 圖、說明、來源 | 一張圖配文字 |
| 5 | 圖與數字卡 | 圖、兩張數字卡、說明、來源 | 一張圖配關鍵數字 |
| 6 | 表格 | 表、備註、來源 | 需求對照、比較表 |
| 7 | 兩欄對照 | 兩張卡片、來源 | 分類、前後對照 |
| 8 | 結論頁 | 三張數字卡、論述框、來源 | 結論與待決事項 |
| 9 | 只有標題 | 來源 | 流程圖、卡片格等自行排版的頁 |
| 10 | 空白 | 無 | 整頁圖 |

- 內容填進版面的佔位框，不另外加文字方塊取代佔位框；圖片與表格插入後會自動落進佔位框。
- 數字卡、兩欄卡片與論述框各是一個文字框，以階層區分：第一階是數字或欄標題，降一階（Tab）是說明，
  數字卡再降一階是備註。
- 標題寫成「主題：結論句」。除封面、章節頁與空白外，每頁都有「來源」佔位框，填報告的圖表編號或
  `output\` 的檔名。
- 頁尾的文件編號與版次由「插入 → 頁首及頁尾」一次套用到全部投影片。

### 5.3 品牌包

本 repo 公開，`templates/` 的範本不含任何單位的標誌與名稱。品牌包的位置、內容與標誌規則見 `pxa-cis` §1、§2、§7。

- 產出簡報時先找品牌包內的品牌範本；找不到就用 `templates/` 的中性範本，並在回報中說明用的是哪一份。
- 品牌範本由 `scripts/build_template.ps1` 加上 `-LogoColor`、`-LogoWhite` 產生，版面與中性範本相同。
