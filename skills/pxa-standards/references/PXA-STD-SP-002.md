**更新日期：** 2026-11-18 (GMT+8)  
**狀態：** Draft

## 1. 範圍與讀者模型

### 1.1 目的

本文件定義 PXA 技術報告（TR，SP-001 §2.1）的本文骨架、依報告性質之裁剪規則、前頁模板、語言與格式規則、表格 Schema 與品質檢核。所有技術報告共用同一份骨架與同一份 Word 範本；研究、設計、測試之差別只在哪些章節必要（§3.1）。治理規則（類別、編號、審查、發行、證據品質）歸 PXA-STD-SP-001；本文件與其互不重複定義。

規範語法（必須/禁止/建議/可選）與 [S]/[H] 判定方式標註依 SP-001 規範語法節。

### 1.2 讀者模型（4-Slot Model）

PXA 技術報告預設四類讀者。具體角色名稱與關注重點由專案 Profile 定義。

| Slot | 通用角色 | 典型關注重點 | 時間預算 | 閱讀路徑 |
|:----:|---------|-------------|:--------:|----------|
| **R1** | 決策者 | 結論、狀態、風險、資源 | 5 分鐘 | 摘要 → 結論 |
| **R2** | 專案管理者（PM / SE） | 進度、TBD/TBC、風險、下游影響 | 15 分鐘 | 摘要 → 結論 → 建議 → 待決與風險附錄 |
| **R3** | 跨域工程師 | 輸入/輸出參數、假設、介面規格 | 30 分鐘 | 結論 → 假設 → 參數與交接附錄 |
| **R4** | 技術審查者 | 公式正確性、推導邏輯、驗證方法 | 完整閱讀 | 技術主體全部 → 結論 → 摘錄與計算附錄 |

**設計意涵**：摘要讓決策者 5 分鐘掌握全貌；技術主體讓審查者能完整驗證每步推導；結論與附錄讓跨域工程師直接取用參數。

## 2. 整體結構

### 2.1 三段式結構

所有 PXA 技術報告 **必須** 遵循 ANSI/NISO Z39.18 三段式結構：

| 區段 | 內容 | 頁碼格式 |
|------|------|----------|
| **前頁** | 封面、書名頁、書名頁背面、DAA、文件資訊、修訂紀錄、目錄、圖表清單、摘要、符號表 | 封面不編；其後小寫羅馬數字，書名頁計為 i 不顯示 |
| **本文** | 第 1 章緒論至結論（§3） | 阿拉伯數字，自 1 起 |
| **後頁** | 參考文獻、附錄 | 與本文連續編號 |

### 2.2 前頁要素與頁碼對映

| 頁面 | 包含狀態 | 頁碼 | 顯示 |
|------|----------|:----:|:----:|
| 封面 | 必要 | — | 不編碼 |
| 書名頁 | 必要 | i | 不顯示 |
| 書名頁背面（致謝/免責/可用性/審查等級/與標準之偏離） | 必要 | ii | 顯示 |
| DAA | 必要 | iii | 顯示 |
| 文件資訊（替代 SF-298；含報告性質） | 必要 | iv | 顯示 |
| 修訂紀錄 | 必要 | v | 顯示 |
| 目錄、圖/表清單 | 條件式（本文超過 30 頁時建議） | 接續 | 顯示 |
| 摘要 | 必要 | 接續 | 顯示 |
| 符號表 | 條件式（有公式即必要） | 接續 | 顯示 |

前頁各欄位規則與模板見 §7。

### 2.3 摘要與關鍵字（Z39.14）

| 規範 | 說明 | 判定 |
|------|------|:----:|
| 摘要字數 | 150–300 字，一段 | [H] |
| 摘要類型 | 資訊型（informative），含四要素：目標、方法、結果（含關鍵數字）、結論 | [H] |
| 摘要禁止項 | **禁止** 公式、外部文獻引用、圖表引用、未定義縮寫 | [S]（公式、引用）＋[H] |
| 關鍵字 | ≥ 3 個，涵蓋學科領域/載具類型/分析方法/關鍵技術，英文為主 | [H] |

文件資訊頁之摘要欄與「摘要」一節內容一致。

## 3. 本文結構

### 3.0 骨架（順序固定）[S]

所有技術報告採同一份骨架（對標 NASA Technical Publication 之內文架構，以下稱 TP 骨架）。骨架之節序固定；技術主體章之數量、名稱與內容依報告性質裁剪（§3.1）。

| 順序 | 節 | 內容 | 必要性 |
|:----:|----|------|:------:|
| 1 | 摘要（Abstract） | §2.3 | 必要 |
| 2 | 符號表（Nomenclature） | 符號/定義/單位三欄；縮寫列於表後 | 有公式即必要 |
| 3 | 1. 緒論（Introduction） | §3.2 | 必要 |
| 4 | 2..N 技術主體章 | §3.3，依報告性質 | 依 §3.1 |
| 5 | N+1. 結論（Conclusions） | §3.5，逐條 [C-n]；建議與適用範圍 | 必要 |
| 6 | 參考文獻（References） | §4.3 | 有引用即必要 |
| 7 | 附錄 A, B, …（Appendix） | §6 | 依 §3.1、§6 |

| 約束 | 說明 |
|------|------|
| 節序固定 | 上表之先後順序 **禁止** 調換 |
| 標題格式 | 章為 `##`、節為 `###`、小節為 `####`，至多三層編號（X.Y.Z）；標題雙語「中文（English）」（§4.1） |
| 第 1 章 | 緒論之標題 **必須** 以 `## 1.` 開頭——此為前頁與本文之分界，頁碼自此改為阿拉伯數字 |
| 章數不限 | 技術主體章可依內容增減；細節下放附錄，正文保持主線 |

原 Part 1–6 結構、TP 合成結構與 Quick/Update 變體自 v3.0 起退役（裁定 #12）；Part 6 之表格改為可選附錄（§6）。

### 3.1 報告性質與裁剪表

每份報告 **必須** 於 MD 頭部 metadata 與文件資訊頁宣告**報告性質** [S]：研究、設計、測試，三者之一；一份報告兼具兩種性質時以「＋」並列（例：設計＋測試），其必要章節取聯集。報告性質只決定哪些章節必要，不影響編號、審查等級、範本與版面。

| 章節 | 研究 | 設計 | 測試 |
|------|:----:|:----:|:----:|
| 前頁、摘要、緒論、結論、參考文獻 | 必要 | 必要 | 必要 |
| 文獻回顧 | 必要 | 可選 | 可省 |
| 理論與建模 | 必要 | 必要 | 可省，引用即可 |
| 需求與設計基線、取捨研究 | 可省 | 必要 | 可省 |
| 測試項目、通過準則、組態、偏差紀錄 | 可省 | 可選 | 必要 |
| 逐字摘錄附錄 | 必要 | 有引用即必要 | 有引用即必要 |

| 性質 | 判斷問句 | 典型例 |
|------|----------|--------|
| 研究 | 是否在建立一個可被其他報告引用的通則或方法？ | 跨專案之單一議題深度研究、文獻整理與推導 |
| 設計 | 是否在針對具體需求選定方案、定出參數或模型？ | 構型選擇、尺寸決定、模型建立 |
| 測試 | 是否在依既定程序量測並判定通過與否？ | 台架測試、模型對量測之驗證、飛行測試 |

「必要」之章節缺漏視為不合規 [S]（以章節標題關鍵字判定，§8.1）；「可選」「可省」由作者決定，省略時不需說明。裁剪以外之偏離 **必須** 記於書名頁背面「與標準之偏離」。

### 3.2 緒論（Introduction）

緒論採五段式，節序固定：

| 節 | 內容 | 必要性 |
|----|------|:------:|
| 1.1 研究動機（Motivation） | 技術問題之工程脈絡；為何現在要做 | 必要 |
| 1.2 文獻回顧（Literature Review） | 依 L1/L2/L3 標註；結構＝現況 → 缺口 → 本報告定位。研究性質之 L2 **建議** ≥ 5 筆（協調制，SP-001 §5.5）[S]（計數回報） | 依 §3.1；省略時此節改為「相關文件」，列出所依據之既有報告與規格 |
| 1.3 研究目標（Objectives of Study） | 具體目標或待回答之問題（可條列） | 必要 |
| 1.4 主要貢獻（Principal Contributions） | 與結論 [C-n] 逐條對映 | 必要 |
| 1.5 章節安排（Organization of the Document） | 各章與附錄之內容 | 必要 |

### 3.3 技術主體章

技術主體之章名與章數由作者依內容決定。各性質之必要內容如下，可各自成章或合併成章，但 **必須** 能由章節標題辨識。

**研究與設計共用——理論與建模**：

| 內容 | 要求 |
|------|------|
| 理論基礎與數學模型 | 每個方程標來源 `[Author Year, Eq.X]`（§4.3）；公式五元素（§4.4） |
| 假設 | A-n 編號，每條附合理性與影響；Schema 見 §5.10 |
| 驗證比較 | 與文獻、實驗或另一方法對比；標佐證旗標 ✓/⚠（SP-001 §5.2） |

**設計——需求與設計基線、取捨研究**：

| 內容 | 要求 |
|------|------|
| 需求與約束 | ID／類型（法規/任務/環境/專案）／描述／來源 |
| 設計基線與上游輸入 | 參數／數值／單位／來源（SP-001 §5.4） |
| 取捨研究 | 存在多個候選方案時依 SP-001 §7 格式 |
| 設計結果 | 選定方案、關鍵參數與裕度；合規矩陣（§5.3）可置於正文或附錄 |

**測試——測試項目、通過準則、組態、偏差紀錄**：

| 內容 | 要求 |
|------|------|
| 測試項目與通過準則 | 每個測試項目有 ID、對應之需求或模型主張、量測量、通過準則；尚未訂定準則者明寫「未訂定」，不得事後補訂（Schema §5.12） |
| 測試組態 | 受測件、軟硬體版本、儀器與資料來源、環境條件（Schema §5.13） |
| 測試程序 | 步驟與資料處理方法，足以讓第三方重現 |
| 測試結果 | 逐項對照通過準則之結果與判定；圖表附文字說明 |
| 偏差紀錄 | 與計畫或程序不符之處、缺少之量測、異常事件及其處置（Schema §5.14）；無偏差時明寫「無」 |

### 3.4 敘事與論證規則

| 規則 | 說明 | 判定 |
|------|------|:----:|
| 三種支撐 | 每個技術主張 **必須** 落在推導、數據或引用三者之一；三者皆無之句子不寫進技術主體 | [H] |
| 引用嵌入行文 | 引用 **必須** 嵌入行文並附具體觀點，**禁止** 段尾堆疊 | [H] |
| 先提後現 | 圖、表、式 **必須** 先於內文提及再出現；表與圖前後有文字說明其目的與結論 | [H] |
| 符號先定義 | 正文使用之符號 **必須** 列入符號表 | [H] |
| 局部與全域 | 技術主體只寫單一主題內之局部意義；跨主題之綜合判斷、方案選定與總結歸結論章 | [H] |
| 主線精簡 | 完整推導、原始數據、長表下放附錄 | [H] |

寫作深度與口吻之標竿見 scribe skill 之 `tp-writing-guide.md`；段落模式與句型參考 writing-examples（非合規條件）。

### 3.5 結論（Conclusions）

結論章自成體系——僅讀摘要與結論即可掌握完整結論。

| 規則 | 說明 | 判定 |
|------|------|:----:|
| 禁止新資料 | **禁止** 引入技術主體未呈現之新資料或新分析 | [H] |
| 可追溯 | 每條結論 **必須** 可追溯至技術主體之具體章節；**禁止** 重複推導過程 | [H] |

**結論格式** [S]（三要素，所有報告性質適用）：

```markdown
**[C-n]** ★★ {結論陳述}
- **適用條件**：{參數範圍或假設條件}
- **限制**：{不適用情況}
```

| 要求 | 說明 | 判定 |
|------|------|:----:|
| 信度標記 | 每條 [C-n] **必須** 含 ★/⚠（判定依 SP-001 §5.2） | [S] |
| 適用條件 | 每條 **必須** 附明確適用參數範圍或假設條件——**缺適用條件禁止發行**；無法給出者退回技術主體補假設，或降為局部討論 | [S] |
| 限制聲明 | 每條 **必須** 明確說明不適用情況 | [S] |

結論 **建議** 4–8 項。結論章 **可選** 再分節：

| 節 | 內容 |
|----|------|
| 適用範圍（Applicability） | 模型、方法或測試結果可用與不可用之範圍 |
| 建議（Recommendations） | ID（R-n，依優先級排序）／建議行動（動詞開頭）／解決之問題／關聯結論；高優先級 ≤ 3 項 |

### 3.6 後頁

參考文獻（有引用時必要）之後為附錄（§6）。附錄 **必須** 以大寫字母依序命名、有標題、在正文中至少引用一次。

### 3.7 撰寫順序

```
文獻回顧（或相關文件）→ 技術主體章（逐章）→ 結論 → 緒論其餘各節 → 摘要（最後）
→ 前頁 → 符號表整併 → 參考文獻 → 附錄
```

先確立知識基礎與結果，摘要與緒論最後提煉。

## 4. 語言與格式規則

### 4.1 段落與語言風格

每段 150–400 字，「主題句 → 論證 → 結論」結構。

| 面向 | 規範 |
|------|------|
| 語態 | 主動語態優先——✓「本報告採用...」 ✗「...被採用」 |
| 主詞 | 明確主詞——✓「Osprey 的巡航速度為...」 |
| 數據 | 具體數值——✓「誤差 ±8.5%」 ✗「誤差較小」 |
| 結論 | 明確判斷——✓「滿足約束，裕度 12%」 ✗「大致符合要求」 |
| 語言 | 繁體中文；技術術語、法規名稱、變數符號保留英文 |

**正式化書寫規範（v2.2 新增，裁定 #11）**：

1. **繁體中文優先**：正文一律以繁體中文行文。專有名詞於**首次出現**時以「中文（English, 縮寫）」格式括註——例：「元件模態合成法（Component Mode Synthesis, CMS）」——其後沿用中文名稱或已定義之縮寫，全文避免中英文大量夾雜。變數符號、式號、程式碼、規格代號維持英文原文，不在此限。
2. **標題雙語**：章節標題採「中文（English）」格式——例：「## 摘要（Abstract）」「## 1. 緒論（Introduction）」。骨架各節（摘要／符號表／緒論／結論／參考文獻）同樣適用；check_sp 之必要節偵測已容許雙語標題（§8.1）。
3. **補充說明正式化**：補充、限定與提醒一律以正式敘述句融入行文，**不採括號夾註或口語化附記**——「（⚠ 原文掃描不清）」改寫為「須注意，原文掃描品質不佳，該式係數尚待覆核」；「（其實這裡可以簡化）」之類口語附記禁止。[C-n] 之信度標記 ★／⚠ 為既定格式元素，不在此限。
4. 本規範屬 [H] 人審項（§8.2）；標題雙語偵測屬 [S]（§8.1）。

### 4.2 禁止用語 [S]

| 禁止用語 | 替代方式 |
|---------|---------|
| 「大約」「差不多」 | 具體數值 ± 誤差 |
| 「應該可以」「可能」 | 「滿足/不滿足」＋條件 |
| 「眾所周知」 | 引用來源 |
| 「顯然」「很明顯」 | 展開推導 |
| 「等等」「之類的」 | 完整列舉 |
| 「顯著影響」 | 「對 X 造成 ±Y% 變化」 |
| 「關鍵約束」 | 「敏感度最高的約束」/「Binding 約束」 |
| 「密切相關」 | 因果鏈或相關係數 |
| 「大幅提升/下降」 | 「提升/下降 X%」 |

### 4.3 引用格式與查核

**行內引用格式**（必須）：`[Author Year, §X.Y]`，嵌入行文附具體觀點與物理量單位。

| 規則 | 說明 | 判定 |
|------|------|:----:|
| 禁止記憶引用 | 每次引用 **必須** 當下查核原文；無法查證之數據 **禁止** 引用，改定性陳述＋`[來源待補]` 或 `⚠ UNVERIFIED` | [H] |
| 物理量標註 | 引用數值 **必須** 標註物理量名稱與單位 | [H] |
| 文獻層級標註 | 依 SP-001 §5.1；必須 | [H] |
| 多作者 | 首位＋et al.：`[Ugwueze et al. 2023]` | [H] |
| 百分比/範圍值 | **必須** 附頁碼或章節號：`[Yu 2020, p.12]` | [H] |
| 同一數值多文獻 | 全部列出分號分隔：`[A 2020; B 2021]` | [H] |
| 內部自引 | `[PXA-{STRN}, §Y]`＋`[L1]` | [H] |

**高風險情境**：同一數字多文獻（標註物理量區分）、百分比範圍（附頁碼）、跨文獻比較表格（每格獨立標註來源）。

### 4.4 公式五元素

每個 display 公式 **必須** 包含：

| # | 元素 | 位置 | 判定 |
|:-:|------|------|:----:|
| 1 | 引入句（物理意義與來源） | 公式前 | [H] |
| 2 | 公式本體——`$$` 三行格式（`$$` 開頭與結尾各佔獨立一行） | 獨立行 | [S] |
| 3 | 符號表（符號/定義/單位） | 公式後 | [H] |
| 4 | 適用條件（假設、範圍、限制） | 符號表後 | [H] |
| 5 | 應用句（代入數值＋結果＋物理解釋） | 適用條件後 | [H] |

**符號處理彈性**：≥ 4 個符號 **必須** 獨立符號表；< 4 個 **可選** 嵌入敘事（「其中 X = ... 取自 [來源]」）。段落文字 **禁止** 內嵌運算過程——計算一律 `$$` 區塊。

### 4.5 提示區塊（Callout Blocks）

用於嵌入**非正文**輔助資訊，不影響主論證結構：

| 類型 | 語法 | 用途 |
|:----:|------|------|
| `NOTE` | `> [!NOTE] **{可選標題}**` | 物理意義、概念補充 |
| `IMPORTANT` | `> [!IMPORTANT]` | 文件定位、使用限制、重要警告 |
| `TIP` | `> [!TIP]` | 典型數值參考、工程經驗值 |

規則：置於相關段落**正後方**；每個 `###` 節至多 2 個；**禁止** 取代正文論證；不計入篇幅判定；多段內容須以空行 `>` 分隔（Typora 渲染）。

### 4.6 章分頁 [S]

| 項目 | 規則 |
|------|------|
| 章（`##`）之間 | **必須** 插入 `<div style="page-break-after: always;"></div>`＋`---` |

**技術正確性**：公式推導正確；數值計算正確；單位一致；參數範圍合理；每個引用已查核原文；逐字摘錄與原文一致（抽驗 ≥ 20%）。

**完稿**：無「⚠ UNVERIFIED」「[來源待補]」殘留；數值有效位數正確（SP-001 §6）。
